    CLI commands¶

    Run migrax help <command> for the same information in the terminal. Run every command from the service folder (the one with pom.xml or build.gradle), or pass --dir <path>.

    Options for every command¶

    Option Meaning
    --dir <path> Project folder (default: current folder)
    --no-build Do not run Maven/Gradle; use the classes and dependencies from the last build
    --refresh Re-resolve dependencies even if cached
    --json Machine-readable output (plan, status, check, lint, drift, diff, verify)
    --verbose, -v Show debug output, Hibernate's own log and stack traces
    --no-input Never ask questions (the default when input is not a terminal)

    Exit codes¶

    Code Meaning
    0 Success
    1 Error, failed check, or failed migration
    2 Differences found: check (entity changes without a migration), drift (database differs), diff (the two databases differ)

    Getting started¶

    init¶

    migrax init

    Creates the .migrax folder and the migration folder, then shows the entity package, database, dialect and naming Migrax detected. Safe to run more than once.

    Option Meaning
    --package <name> Entity package (default: MIGRAX_PACKAGE or pom groupId)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --naming <strategy> spring, jpa, jpa-snake or micronaut (default: detected)
    --dir <path> Project folder (default: current folder)

    doctor¶

    migrax doctor

    Runs every check Migrax needs and explains how to fix anything that fails. Exits with code 1 when a check fails.

    Option Meaning
    --json Machine-readable output
    --env <name> Environment for migrations marked '-- migrax:env'
    --package <name> Entity package (default: MIGRAX_PACKAGE or pom groupId)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --extractor <mode> auto, hibernate, eclipselink, openjpa, spring-data-jdbc, micronaut-data or annotations (default: auto)
    --schema-file <path> SQL file with the desired schema, instead of entities
    --scratch-url <url> Empty database to read the schema file in (default: Docker)
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    mcp¶

    migrax mcp [--allow-generate]

    Runs a Model Context Protocol server on stdin/stdout, so AI assistants such as Claude Code can call status, check, plan, lint, drift, doctor, verify and show_migration as tools and read their JSON results. It never changes a database: migrate, rollback, repair and clean are not offered. --allow-generate also offers generate, which writes migration files for the person to review. Claude Code: claude mcp add migrax -- migrax mcp. See Using Migrax with AI assistants.

    Option Meaning
    --allow-generate Also offer the generate tool (writes migration files)
    --dir <path> Project folder (default: current folder)

    import¶

    migrax import flyway|liquibase

    flyway: records every migration in flyway_schema_history as applied, so Migrax continues where Flyway stopped; V*__ and R__ files keep working. liquibase: writes a baseline migration with the current schema and records it. Afterwards run migrax generate to start managing changes, and remove Flyway or Liquibase from the project. See Switching from Flyway or Liquibase.

    Option Meaning
    --table <name> Flyway history table (default: flyway_schema_history)
    --name <name> Migration file name (default: next number + description)
    --schema <name> Database schema to read
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --dialect <name> postgresql, cockroachdb, yugabytedb, mysql, mariadb, tidb, sqlserver, oracle, h2, hsqldb, derby, sqlite
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    Everyday¶

    baseline¶

    migrax baseline <migration> [--dry-run] --yes

    For a database whose tables already exist (created by hand, by a script or by another tool): records every versioned migration up to and including <migration> as applied without running it. migrax migrate then runs only the later ones. Refused when the database already has migration history. --yes confirms the change to migration history.

    Option Meaning
    --dry-run Show what would happen without doing it
    --yes, -y Confirm without asking
    --json Machine-readable output
    --env <name> Environment for migrations marked '-- migrax:env'
    --schemas <a,b> Run for each schema (multi-tenant)
    --lock-timeout <time> Wait this long while another process migrates (e.g. 2m)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --java-package <pkg> Package of Java migrations (default: db.migration; db.<name> with --database)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    generate¶

    Alias: makemigrations

    migrax generate [--name <name>] [--allow-destructive [--keep-data]] [--safe]
migrax generate --zero-downtime [--name <name>] [--allow-destructive]
migrax generate --contract

    Compiles the project if needed, compares the entities with .migrax/snapshot.json and writes a numbered SQL file plus a rollback script (rollback/<file>). On the first run, with no snapshot, the current database schema is the baseline: its tables are written to 0001_baseline.sql, which that database records as applied without running it. When a column or table seems renamed, Migrax asks (or pass --rename / --rename-table) so the data is kept. Drops need --allow-destructive; with --keep-data, dropped tables and columns go to migrax_backup_* tables and the rollback script restores them (migrax backups lists and drops those tables). --safe (PostgreSQL, CockroachDB) builds indexes and constraints on existing tables without blocking writes, in a second migration. --zero-downtime splits the change so the old and new application versions can run at the same time: an expand migration now (new columns and tables, a renamed column kept equal to its old name by a trigger, a renamed table's old name as a view) and a contract migration for the next release (drops, NOT NULL, narrower types, new constraints). The contract migration waits in .migrax/pending/; generate --contract adds it to the migration folder. Always review the generated SQL; Migrax lints it for you.

    Option Meaning
    --name <name> Migration file name (default: next number + description)
    --allow-destructive Allow drops and narrowing type changes
    --keep-data Keep dropped data in backup tables the rollback restores
    --safe Non-blocking indexes and constraints (PostgreSQL, CockroachDB)
    --zero-downtime Split into an expand migration now and a contract one later
    --contract Add the waiting contract migrations to the migration folder
    --rename t.old=new Treat a column change as a rename (comma-separated)
    --rename-table old=new Treat a table change as a rename
    --no-input Never ask questions
    --lock-timeout <time> Wait this long while another process migrates (e.g. 2m)
    --dialect <name> postgresql, cockroachdb, yugabytedb, mysql, mariadb, tidb, sqlserver, oracle, h2, hsqldb, derby, sqlite
    --package <name> Entity package (default: MIGRAX_PACKAGE or pom groupId)
    --naming <strategy> spring, jpa, jpa-snake or micronaut (default: detected)
    --extractor <mode> auto, hibernate, eclipselink, openjpa, spring-data-jdbc, micronaut-data or annotations (default: auto)
    --schema-file <path> SQL file with the desired schema, instead of entities
    --scratch-url <url> Empty database to read the schema file in (default: Docker)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --schema <name> Database schema to read
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --refresh Re-resolve dependencies even if cached
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    migrate¶

    migrax migrate [--to <migration>] [--sql | --dry-run] [--resume] [--schemas a,b]

    Applies pending SQL and Java migrations in order, then new or changed repeatable R__*.sql migrations, with beforeMigrate/afterMigrate callbacks and ${placeholders}. --to applies versioned migrations only up to and including the given one; repeatable migrations then wait for the next migrate without --to. --sql prints the SQL script of what migrate would do, for a DBA to review and run with the database's own tool; nothing changes. --dry-run lists and lints pending migrations without changing the database. --schemas runs the migrations once per schema (multi-tenant). --resume re-runs a failed migration only if it is marked -- migrax:resume-safe.

    Option Meaning
    --to <migration> Last migration to apply, keep or squash up to
    --env <name> Environment for migrations marked '-- migrax:env'
    --sql Print the SQL script without running it (for a DBA)
    --dry-run Show what would happen without doing it
    --json Machine-readable output
    --resume Re-run a failed resume-safe migration
    --lock-timeout <time> Wait this long while another process migrates (e.g. 2m)
    --schemas <a,b> Run for each schema (multi-tenant)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --java-package <pkg> Package of Java migrations (default: db.migration; db.<name> with --database)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    lint¶

    migrax lint [files...] [--all] [--strict] [--json]

    Checks pending migrations (or the given files, or --all) for statements that block tables, fail on existing data, or break running application instances, and suggests safe alternatives. Exits with 1 on errors, or on warnings with --strict. Silence a finding with -- migrax:lint-ignore MX001 before the statement.

    Option Meaning
    --all Lint every migration, not only pending ones
    --strict Fail on warnings too
    --json Machine-readable output
    --dialect <name> postgresql, cockroachdb, yugabytedb, mysql, mariadb, tidb, sqlserver, oracle, h2, hsqldb, derby, sqlite
    --url <jdbc-url> Database URL (default: application config)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    verify¶

    migrax verify [--url <scratch-db>] [--skip-rollbacks]

    Starts a throwaway database (H2, HSQLDB and Derby in memory, Docker for other engines), applies every migration, then checks the result: Hibernate's schema validation when Hibernate is in the project, otherwise a structural comparison with the entities. It also tests every rollback script on its own: it rolls the migration back, applies it again and checks that the schema is the same, so a broken script is named.

    Option Meaning
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --image <image> Docker image for the throwaway database
    --skip-rollbacks Do not test rollback scripts
    --json Machine-readable output
    --env <name> Environment for migrations marked '-- migrax:env'
    --dialect <name> postgresql, cockroachdb, yugabytedb, mysql, mariadb, tidb, sqlserver, oracle, h2, hsqldb, derby, sqlite
    --package <name> Entity package (default: MIGRAX_PACKAGE or pom groupId)
    --naming <strategy> spring, jpa, jpa-snake or micronaut (default: detected)
    --extractor <mode> auto, hibernate, eclipselink, openjpa, spring-data-jdbc, micronaut-data or annotations (default: auto)
    --schema-file <path> SQL file with the desired schema, instead of entities
    --scratch-url <url> Empty database to read the schema file in (default: Docker)

    diff¶

    migrax diff <source-url> [--sql] [--json]

    Compares the schema of the source database (for example staging) with the project's database (for example production; set it with --url) and lists the changes that would make the project's database match: tables, columns, types, keys, indexes, checks and comments. --sql prints them as one SQL script to review. Both must be the same kind of database. Exits with code 2 when they differ. The source's user and password come from --source-user and --source-password-file, MIGRAX_SOURCE_USER and MIGRAX_SOURCE_PASSWORD, or the URL itself.

    Option Meaning
    --sql Print the SQL script without running it (for a DBA)
    --json Machine-readable output
    --source-user <name> User of the source database
    --source-password-file <path> Read the source database's password from a file
    --schema <name> Database schema to read
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution

    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    environments¶

    migrax environments [--environments <a,b>] [--no-drift] [--timeout <duration>] [--json]

    Asks each environment's database (migrax.environments.<name>.url) which migrations it has applied, lists what is pending there and whether its schema drifted from the snapshot, without changing anything. Migrations marked -- migrax:env count only in the environments they name. Exits with code 1 when an environment can't be reached or a migration failed, changed or is missing there, and 2 when drift is found; pending migrations alone exit with 0.

    Option Meaning
    --environments <a,b> Environments to show, in this order (default: all configured)
    --no-drift Don't compare the schemas with the snapshot
    --timeout <duration> How long to wait for each database (default: 30s)
    --json Machine-readable output
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --java-package <pkg> Package of Java migrations (default: db.migration; db.<name> with --database)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    --schema-file <path> SQL file with the desired schema, instead of entities
    --scratch-url <url> Empty database to read the schema file in (default: Docker)
    --url <jdbc-url> Database URL (default: application config)

    Maintenance¶

    squash¶

    Alias: squashmigrations

    migrax squash --to <migration> [--optimize]

    Writes one migration that replaces all migrations up to --to. Databases that already applied them record it without running it; new databases run just the squashed file. --optimize writes only the resulting schema (data statements are dropped). Delete the old files once every environment has run migrate.

    Option Meaning
    --json Machine-readable output
    --to <migration> Last migration to apply, keep or squash up to

    repair¶

    migrax repair <migration>... --action applied|retry|forget --yes

    Use only after inspecting the database.

    • --action applied: every statement took effect, so record the migration as applied.
    • --action retry: you restored the database, so clear the failure and let it run again.
    • --action forget: you deleted applied migration files on purpose, so remove them from the history. The database keeps the changes they made. Accepts several migrations at once.

    --yes confirms the change to the migration history.

    Option Meaning
    --json Machine-readable output
    --action <action> applied, retry or forget
    --yes, -y Confirm without asking
    --lock-timeout <time> Wait this long while another process migrates (e.g. 2m)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --locations <paths> Migration folders, comma-separated (e.g. filesystem:db/sql)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    clean¶

    migrax clean [--dry-run] [--yes]

    Empties the database so migrax migrate can rebuild it from the migrations: drops every table (the migration history too), view and sequence in the configured schema. Data is deleted and can't be restored. Migration files and the snapshot are not touched. Asks before dropping; --yes confirms without asking. --dry-run lists what would be dropped. Set MIGRAX_CLEAN_DISABLED=true on servers where clean must never run.

    Option Meaning
    --json Machine-readable output
    --dry-run Show what would happen without doing it
    --yes, -y Confirm without asking
    --lock-timeout <time> Wait this long while another process migrates (e.g. 2m)
    --url <jdbc-url> Database URL (default: application config)
    --user <name> Database user
    --password <secret> Database password (prefer env vars)
    --password-file <path> Read the database password from a file (mounted secret)
    --schema <name> Database schema to read
    --schemas <a,b> Run for each schema (multi-tenant)
    --classpath <paths> Extra classpath; skips Maven/Gradle resolution
    --no-build Do not run Maven/Gradle; use compiled classes
    --database <name> Work on migrax.databases.<name> instead of the default database
    --dir <path> Project folder (default: current folder)

    backups¶

    migrax backups [--drop [<migration>] --yes]

    Lists the migrax_backup_* tables that migrations generated with --keep-data keep dropped data in; their rollback scripts restore it from there. Once you are sure you won't roll a migration back, drop its backups: --drop removes them all, or only those of one migration (--drop 0005). Asks before dropping; --yes confirms without asking.

    Option Meaning

    --url <jdbc-url> Database URL (default: application config)
