    Run migrax migrate

    Apply it from the command line, in CI, or when the application starts.

    See it in 30 seconds

    Add a field to an entity, and Migrax writes the SQL.

    Customer.java
    @Entity
@Table(name = "customers")
public class Customer {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    public Long id;

    public String email;
    public String phone;      // new
}
    0002_add_customers_phone.sql
    -- Generated by Migrax 0.2.0 for postgresql

ALTER TABLE customers ADD COLUMN phone varchar(255);

    The migration is plain SQL you can read, review and commit, with a rollback script next to it. Nothing is hidden: you can edit every statement before it runs.

    Why teams use Migrax

    Everything a migration needs, checked before it reaches production.

    • Migrations written for you

      Change an entity, run migrax generate. Tables, columns, keys, indexes, join tables, element collections, sequences and inheritance come out exactly as Hibernate maps them.

    • Checked before production

      Every migration is linted for statements that lock big tables, fail on existing rows or break running instances. migrax verify has your Hibernate version validate the result.

    • Rollback included

      Each generated migration comes with a rollback script, and verify proves it works by rolling everything back and forward again.

    • Asks before it loses data

      A dropped column that looks renamed? Migrax asks, and renames it so the data stays. Drops only happen when you say --allow-destructive.

    • Catches manual changes

      migrax drift compares the live database with what your migrations produce and lists every difference, including columns someone made narrower.

    • Zero setup

      Run it in your service folder. It compiles the project, finds the dependencies and reads the database settings from your application configuration.
